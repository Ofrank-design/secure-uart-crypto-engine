# Cryptographic Design

- AES-128-GCM, 96-bit IV, full 128-bit tag (NIST SP 800-38D). Only the AES encrypt direction is implemented (GCM needs no other).
- Counter blocks: J0 = IV || 0x00000001; data counters start at 2 (inc32). Tag = GHASH(AAD, C, len) XOR E(K, J0).
- Verification: FIPS-197 vectors (3), and 108 GCM vectors generated by OpenSSL (via python `cryptography`) including NIST cases 1-4
  (cross-checked in `scripts/gen_gcm_vectors.py`). Coverage: empty/partial/multi-block, AAD 0..33 bytes, enc/dec, tag/IV/ciphertext/AAD tamper.
- Directional domain separation: AAD includes TYPE (01 request, 81 response), so a captured response cannot be replayed as a request.
- Nonce spaces: device = DEVICE_ID(4B) || counter(8B), host nonces must differ in the first 4 bytes (enforced: error 05).
  Same key in both directions is acceptable only because of this separation; the host must also never reuse its own nonces.
- Nonce counter durability: counter+1 is written to NV and acknowledged BEFORE the value is used. Skipped values after a crash are harmless.
- Plaintext hold-back: decrypt output is collected in a private buffer; released only after tag success AND the replay SEQ is durably stored.
- Key lifecycle: build-time test key (`KEY_INIT`) or `KEY_INIT_VALID=false` + trusted `key_load` port; `zeroize` clears immediately.
  The UART cannot load or read keys.
- Tag comparison is a single-cycle 128-bit parallel compare (no data-dependent latency).
- Not provided: side-channel resistance, fault-injection resistance, authenticated responses for type 82/E0.

## Interface mapping to spec section 6.3
| Spec signal | Implementation |
|---|---|
| start / busy / done / error | `start` / `busy` / `done` / `error` (start-while-busy pulse) |
| key, nonce | `key`, `iv` (96-bit) |
| associated_data, input_data | block stream on `in_block`, `in_valid`, `in_ready`, `in_is_aad` |
| input_length | `aad_len`, `data_len` (bytes) |
| output_data, output_length | `out_block`, `out_valid`, `out_bytes` |
| authentication_tag, authentication_ok | `tag_out` (+`tag_in` for decrypt), `auth_ok` |
The contract (when inputs are sampled, backpressure, reset/cancellation, behaviour after failure) is in the header of `rtl/aes_gcm_engine.vhd`.
This is a buffered block-stream interface; streaming and buffered styles are not mixed.

## Key and nonce lifecycle
1. **Provisioning**: build-time test key (lab only) or `KEY_INIT_VALID=false` and a pulse on `key_load` from trusted logic. The UART cannot load, read or change keys.
2. **Use**: the key is read from `key_manager` at the start of each transaction and latched by the engine.
3. **Zeroization**: `zeroize` clears the key and valid flag immediately (priority over `load`); every request is then refused (`E0 04`).
4. **Reset**: restores the build-time initial key state only; NV state (nonce counter, last SEQ) is untouched.
5. **Nonce (device)**: `DEVICE_ID || counter`; the counter is loaded from NV after reset, `counter+1` is written and acknowledged before use, so
   power loss or reset at any point can only skip values, never repeat one.
6. **Nonce (host)**: chosen by the host, must not start with `DEVICE_ID` (enforced); host must never reuse a nonce under the same key.
7. **Rekeying**: loading a new key does not reset the NV counters. Counter exhaustion (2^64) or SEQ exhaustion (0xFFFF) needs NV re-provisioning.
8. **Device replacement / counter rollback**: restoring an old NV image would allow nonce and SEQ reuse; NV content must be protected against rollback (open item).
